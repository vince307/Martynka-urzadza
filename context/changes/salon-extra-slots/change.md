## Notes

Roadmap slice **S-16d** (`### S-16d: Pięć nowych miejsc w salonie`), fourth and last slice of autonomous run `2026-10-15-fix-s16bcd`. PRD refs: FR-016 (costs and order of renovation tasks are room data, start 5–15 stars), FR-019 ("Pokój gotowy!", room list, "poprawki" after the salon is done).

**Outcome:** the child furnishes 5 new places in the salon, 3 variants each, from the gitignored pack `designs/martynka-salon-v2` (P3): curtains, wall shelf, lamp, left plant, pouf. The salon then has 11 slots (33 variants). The architecture before/after pictures are replaced by the pack's curtain-less versions. The right plant stays fixed decoration.

**Author decisions (2026-10-15, binding):**
- The 5 new tasks are APPENDED at the END of `SALON.tasks`, in the order curtains, shelf, lamp, plant (left), pouf. Costs 8–15 (S-17 tunes them).
- Lamp, left plant and pouf show their old look (variant 0) as decoration until bought; their task reads "Wymień …" (e.g. "Wymień lampę") and opens the variant panel.
- Curtains and shelf do not exist before they are bought (bare window, empty wall).
- Completed salons get the new tasks and see "Pokój gotowy!" a second time.

**Save format: STAYS v3, no save migration is expected.** Why: `RoomState` is `{ tasksDone, chosen }`; `tasksDone` counts positions in `SALON.tasks` and appending keeps every existing position (a saved 0..7 still means the same prefix); `chosen` is keyed by slot id and gains new keys only when the child buys a new piece; `validateSave` checks `chosen` values (0|1|2), not slot ids, so a v3 save written before and after this slice has the same shape. A completed salon (`tasksDone` 7) simply has `tasks[7]` (curtains) as its next task, so `roomDone` is false again until the 12th task. The v2→v3 step (`LIFT_V2_SALON`) targets the frozen `SALON_V3_TARGET` (7 tasks) and stays frozen; a lifted v2 salon lands inside the first 7 tasks and then continues into the appended ones. Frozen fixtures in `tests/fixtures/` stay byte-identical. A rollback to the S-16c build is safe: it reads `tasksDone` 8..12 as done (`>= tasks.length`) and ignores the unknown `chosen` keys.

**Source (read-only, never staged):** `designs/martynka-salon-v2/manifest.json` `slots` (now 11, including `curtains`, `wall-shelf`, `lamp-table`, `plant-left`, `pouf`), `layers` (only `plant-right` left), `curtainEdit` (mask + polygons of the edited architecture pixels); `assets/room/architecture-{before,after}.png` (curtain-less); `assets/furniture/{curtains-leaf,curtains-cream,curtains-botanical,shelf-oak,shelf-mint,shelf-arch,lamp-wicker,lamp-flower,plant-fern,plant-ficus,pouf-knit,pouf-oak}.png` (12 new files; `lamp-table`, `plant-left`, `pouf` are the existing pictures, now variant 0). Converted by `npm run art` (`scripts/make-task-art.mjs`, extended; WebP into `public/assets/rooms/salon/`), committed (author consent 2026-10-13).

## Autonomous decisions

1. **Slot ids follow the pack manifest** (`curtains`, `wall-shelf`, `lamp-table`, `plant-left`, `pouf`), as S-16a did for the first six. Rejected: short ids `shelf`/`lamp`/`plant` (they equal old v2 keys in `LEGACY_SALON_V2`, and `shelf` is renamed to `cabinet` by the v2→v3 step — reusing it would be confusing). Would change: research finding a code path where `curtains` (also an old v2-only key) is misread on a v3 save; then a distinct id such as `window-curtains`.
2. **No save migration, format stays v3** (contract + author decision; reasoning in Notes). Would change: the plan needing a field that is not `tasksDone`/`chosen` (e.g. a persisted "done card seen"); then the slice stops at an open PR per the run contract.
3. **The pin test is not rewritten but made explicit** (prefix of the 12-task list + an append-only guard on the full id order) instead of editing `SALON_V3_TARGET`. Would change: nothing in this slice; the frozen table changes only with a v4 format.
4. **Unbought lamp/plant/pouf are decoration only (not holdable, no panel by hold)**; the panel opens from the task button like every slot task. Would change: research showing the author's "Wymień …" flow expects a tap on the piece itself.
5. **Next step is `/10x-research`, not `/10x-plan`**: the slice touches data model (`SlotDef`), drawing (`RoomView`, miniature, `RoomLayer`), hit test, art script, e2e hook and copy; open questions above (furnishings-before content, negative curtain `y`, miniature use) need grounding. Would change: none (the orchestrator dispatches research next).
6. **`MINIGAME_WORDS` unchanged** (new captions do not join the word minigame). Would change: the author asking for the new words.
